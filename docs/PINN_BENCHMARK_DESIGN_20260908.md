# 历史设计草案：从共享 jet 到真实 PINN 训练 v0.1

**后续决策已取代其中的框架/编译方案：统一 PyTorch eager，不开展 JAX/JIT 双轨。**
当前实现和迁移验收协议见 `experiments/torch_benchmarks/README.md`。
下文保留问题定义与讨论过程，不能作为启动旧 JAX 或双轨实验的指令。

状态：设计提案，尚未启动参数梯度性能矩阵或 PINN 训练。
日期：2026-09-08。已完成源码/结果基线：`c71ea6caf49235cd3bb60b31694b7011f62a0ed0`。
本文不修改历史协议、原始结果、论文或现有求值器；不授权新 GPU 作业或推送。

## 1. 核心问题及当前证据

研究对象是给定高阶微分表达式的计算实现：共享方向 jet 与固定线性重构，
是否能在得到相同导数、参数梯度和可比解精度的前提下，降低 PINN 的实际成本。
这不是提出一种新的 PINN loss，也不是比较不同 PDE 或不同训练算法谁更容易收敛。

| 层级 | 任务 | 已有证据 | 能支持的结论 |
| --- | --- | --- | --- |
| A 单项导数 | 同一随机网络的指定高阶偏导 | 第一组 value-only benchmark | 固定微分目标的计算成本 |
| B 多项表达式 | 二维 KdV 型残差向量；一维梯度增强 KdV 标量目标 | T4 共享/线性重构前向结果及逐项校验 | 导数复用与重构的前向收益 |
| C 训练计算 | scalar loss、参数梯度、优化器更新 | 仅本轮小网络梯度烟雾检查 | 仍需验证完整 GPU 训练路径与成本 |
| D PDE 求解 | 带初边值条件的 PINN 收敛 | 尚无 | 仍不能宣称训练加速或已解出 PDE |

本仓库 `g-KdV` 的 g 指 gradient-enhanced；它是 KdV 的梯度增强损失，
不是这里额外引入的 generalized KdV 方程。训练文档建议称 `KdV-gPINN`。
输入导数 f_x、f_t 与网络参数梯度 grad_theta L 是两个不同层次。

历史前向结果、不同 GPU 以及不同 JIT 模式永不合并统计。
原二维 KdV 型例子是三变量残差运算案例，不因为名字相似就替代成一维方程。

## 2. 三个比较对象与公平性

- 固定主基线：现有 coordinate nested JVP，保留 lower-primal reuse，
  不构造完整高阶导数张量，不根据本轮成绩改选其他 AD 基线。
- 主方法：已验证的 shared_jet_linear；KdV 型六方向，KdV-gPINN 五方向。
- 机制消融：原 shared_jet，在 B=400 的计算成本对照中保留。
  原 termwise 结果用于已完成的共享机制分析，不把它当作较弱主基线。

方法之间只更换内部 PDE 导数计算器。模型、参数初始化、点序列、loss 各项、
优化器、精度、数据传输、边界导数计算、验证频率和预算都必须相同。
所有方法一律通过同一个参数反向变换求 grad_theta L。

JAX 的 [value_and_grad](https://docs.jax.dev/en/latest/_autosummary/jax.value_and_grad.html)
要求标量 loss；其一般能力不替代本组合的正确性测试。
官方 API/版本差异见 `experiments/jax_benchmarks/JAX_TRAINING_REFERENCES.md`。

## 3. G0：参数梯度正确性闸门

先做正确性，再计时；不因性能差而换题、改容差或筛除种子。

1. 二维 KdV 型采用 L=mean(R^2)，而不是对残差向量直接调用 grad；
   一维 KdV-gPINN 采用当前完整标量目标。
2. 同参数同点比较 loss 和所有参数叶子的梯度；保存逐叶 max absolute error、
   全局 relative L2、梯度范数。暂定 float32 元素容差 rtol=1e-3, atol=1e-6，
   全局相对 L2 <=1e-3；接近零的梯度同时报告绝对范数，不夸大相对误差。
3. 小型解析/独立 float64 参考与参数方向有限差分检查，覆盖至少五个固定方向；
   使用多个步长确认差分稳定区，不用一次 float32 差分当真值。
   dtype/方向权重须显式一致；不得直接假设现有 float32 工厂已支持 float64。
4. 全宽 GPU 测试：两例、B=3、三个正式种子、三种实现。
5. 相同初始优化器状态下比较一次 Adam 的 loss、grad、更新参数和状态，
   再执行 20 步更新确认无 NaN/Inf、状态确实改变；不要求长程浮点轨迹逐位一致。
6. 与训练任务一致的初边值项和总 loss 必须再做参数梯度检查。

本轮只做了非持久本地诊断：width=4、depth=2、B=3，seeds=71,72，
两例各三种实现共 12 组 loss+parameter-grad 调用通过，全部梯度有限。
相对 JVP 的最大梯度 relative L2 为 7.451459623553092e-6，元素容差通过。
这是 CPU 小网络 smoke；不是完整 G0、GPU backward benchmark 或训练结果。

## 4. G1：loss、loss+grad、真实 step 的计算 benchmark

分别测量三个实际程序，不用两个时间相减冒充精确 backward-only 时间：

- F：完整 PDE scalar loss；二维例由旧 residual-vector 口径升级为 mean(R^2)，
  必须重测，旧向量时间不能直接拿来计算新加速比。
- FG：value_and_grad 返回 loss 与整个参数梯度 pytree。
- STEP：loss + 参数梯度 + 一次 Adam 更新，返回新参数及优化器状态。

主矩阵：两例 × 两个主方法 × B={100,400,1600} × 三个匹配种子。
每种执行模式 12 个 method/case/batch cell、36 条 seed 记录；每条分别测 F/FG/STEP。
原共享消融只在 B=400 做两例 × 三种子，避免把完整训练扩成调参网格。
同一硬件重新测所有比较对象；width=128、depth=4、tanh、float32、最高 matmul 精度。

每项记录冷启动、10 次预热、30 次同步计时的全部样本。F/FG 用同一冻结参数；
STEP 用独立预热副本后恢复初始状态，再真实连续更新，批次序列匹配。
不要将预热后的训练状态作为某个方法独有的起点。初始化、验证、序列化在计时外。
同步覆盖 grad/新参数/优化器状态，而不是只等待一个无关标量。
这是依据 JAX 的 [异步执行说明](https://docs.jax.dev/en/latest/async_dispatch.html)。

显存：报告明确口径的过程高水位和独立的训练 step profiling；不能把 JAX allocator
缓存保留量当成 live activation peak。OOM/超时为正式结果，不私自缩 batch 或 chunk。
F/FG/STEP 的细分显存采用隔离进程，避免前一阶段的高水位污染。

### 编译策略：两个独立轨道

- U：不加外层 JIT，延续用户已固定的现有主线。
- J：建议新增双方对整个相同范围的 train_step 都使用 JIT 的工程对照。
  这是待确认的新协议，不替换 U，不修改既有成绩，也不在本轮启动。
  仅在 J 也验证后，才讨论面向常规编译式 JAX 训练的性能结论。

每个轨道都记录 cold trace/compile、稳态执行和 total wall time。
J 保持参数、优化器状态和批次为动态输入，固定形状，不闭包捕获变化参数，
不每步重新创建函数。编译超时或无法编译保留为结果；不能只给一方编译。
见 JAX [JIT 文档](https://docs.jax.dev/en/latest/201/jit.html)。

## 5. G2：首个真正的训练任务——一维 KdV-gPINN

建议先完成一个定义完整且有解析真解的问题；二维 KdV 型先保留 G1 计算任务。
它的初边值问题与可靠参考解尚未定义，不在同一轮临时补齐并直接称训练 benchmark。

### 方程、区域及解析解

    u_t + u u_x + 0.0025 u_xxx = 0,
    x in [-1,1], t in [0,1].

选择单孤子

    u*(x,t) = 0.75 sech^2(5(x + 0.5 - 0.25 t)).

这是本提案选择的受控解析解案例，不宣称复现外部论文的训练数据集。
设 z=tanh(5(x+0.5-0.25t))，则 U=3(1-z^2)/4、
D_x=5(1-z^2)D_z、D_t=-D_x/4，直接代入即可检查无外力残差恒为零。
本轮以有理系数多项式运算代入核对，残差精确等于 0；这仅验证解析参考解，
不等于 PINN 训练已经成功。

给定初值 u(x,0)=u*(x,0)。有限区间使用三条精确边界迹：
u(-1,t)、u(1,t)、u_x(1,t)，均从解析解取得；不得将非零尾部冒充周期或零边界。
这类三条边界迹结构可参见 [KdV 有限区间边值研究，式(1.7)](https://arxiv.org/html/1703.08154)。
引用说明边界结构来源，不将该文的特定系数定理直接当成本例的证明。
参考解还要有独立解析导数、初边界兼容性和数值残差测试。

### 训练 loss 与候选固定设置

    L = L_f + 0.001 (L_fx + L_ft) + 10 L_IC + 10 L_BC,
    L_BC = MSE(u(-1,t)-u*(-1,t))
         + MSE(u(1,t)-u*(1,t))
         + MSE(u_x(1,t)-u*_x(1,t)).

各 MSE 分别取均值，不让不同点数隐式改变损失权重。边界 u_x 使用两方法共用的
一阶 coordinate JVP 辅助函数；其成本在训练 step 内，不归功于共享重构。
解析内域值只用于验证/最终评估，不作为监督训练标签；否则不再是这份 PINN 协议。

- 模型：当前三层 width-128 tanh 隐藏层 + 标量输出，原初始化，不加 Fourier features。
- 主训练 B_f=400；初值 128 个等距点；边界 128 个等距时间，每时刻包含三条迹。
- 内域点每步从矩形均匀抽样，固定 master seed 的独立流，所有方法重放同一序列。
  这与二维 disk 运算采样不同，必须作为新的 PDE 训练任务配置记录。
- 同批点共享 f/f_x/f_t，物理坐标导数；若以后归一化输入，链式缩放须显式验证。
- Adam lr=1e-3、beta=(0.9,0.999)、eps=1e-8，无 weight decay、梯度裁剪、L-BFGS、
  自适应 loss 权重、残差自适应采样或方法专用参数。
- 预算上限：10,000 更新步或 30 分钟 optimizer-loop 时间，先到者停。
- 主训练两方法 × 三个 seed，共 6 条轨迹/执行轨道。J 轨道获确认后同样 6 条，
  不根据 U 的排名决定是否公布 J。

以上训练超参数属于候选 v0.1，不声称已经足以收敛。正式比较前仅允许一次
独立 seed=20260918、1,000 步的共同基线可行性 pilot，检查初边值实现、loss 尺度、
有限梯度及学习趋势。pilot 不进入正式统计；若无法产生可解释学习，保留记录并
另行修订/冻结训练协议，不能继续盲跑或针对某方法单独调参。

## 6. 精度、时间和成功判据

不用“loss 下降”替代求解成功，也不预设共享 jet 应取得更高精度。

- 解误差：空间-时间相对 L2，并单列 t=1 的相对 L2 和 L-infinity 误差。
- 物理约束：独立验证点上的 PDE residual RMS、梯度残差 RMS、初值与三条边界误差。
  评估导数用共同独立参考路径，避免每种方法只给自己的实现打分。
- 三张核心曲线：解误差 vs step；解误差 vs optimizer-loop 秒数；loss 各项 vs step。
- 首要结果：达到验证相对 L2=1e-2 的时间，辅助阈值 5e-2。
  同时要求初值及每条边界迹的 RMS 误差 <=1e-2、独立 PDE residual RMS <=1e-2，
  均按本例已指定的物理坐标与无额外缩放的量计算；梯度残差另行报告。
  阈值需在两个连续验证时刻满足，以首次时刻记到达时间；没有达到记为
  未达到/右删失，不丢掉失败种子或只对成功子集给加速比。
- 每 100 步验证，固定验证网格 128×51；最终独立测试网格 257×101，
  另有固定随机 residual 验证点。测试真值不用于超参数选择或优化器反馈。
- 固定步数、固定 optimizer-loop 时间、time-to-threshold 三种口径分别报告。
  同一运行轨迹可提供这些指标；公共预算取两方法都有观测覆盖的时段/步数，
  不外推未跑到的 10,000 步结果。
- optimizer-loop 时间含取点/传输、loss、grad、update，不含定期评估和存盘；
  同时提供包含启动编译、评估、存盘的总耗时，不能只展示扣除后的数字。
- 汇报每个种子的原始曲线、成功数、配对比值及范围；三种子不支持夸大的显著性结论。

算法等价不意味着非凸优化的浮点训练轨迹逐步重合。
固定步数精度可比、参数梯度正确，且到达相同误差的耗时更少，才支持训练收益。
不沿用前向实验的 10% gate 作为筛选训练案例的规则；负收益也完整报告。

## 7. 执行顺序与产物

建议顺序：冻结设计 → G0 完整梯度闸门 → G1 参数梯度/step 成本 →
一次共同训练 pilot → 冻结 G2 训练配置 → 匹配正式训练 → 完整回收与评估。
一次实验一个固定源码 worktree 与独立结果目录；核对实际 GPU 预算后排程，
每张 GPU 一次一个训练进程；不并发争用同一张卡或共享可写状态。

每 cell 保存：完整配置、源文件/输入哈希、全部计时、grad 检查、训练/验证曲线、
初始/最终及定期 checkpoint（含 Adam 状态和采样状态）、预测与真解、失败记录、
峰值显存口径、环境锁文件、状态和校验清单。完整回收到本地才报告完成。
本轮只交付设计文件与小型 CPU 诊断事实，不新增训练作业、论文编辑或 GitHub 推送。
